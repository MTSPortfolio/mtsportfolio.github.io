01

Marko-Viz

Efficient frontier calculator

Live Personal project

Marko-Viz computes and plots the efficient frontier for any set of assets. You supply the tickers, the historical window and — this is the important part — your own expected returns. The app returns the mathematical object: the risk/return curve and the weights along it.

It never returns a recommended portfolio. That's a deliberate product decision, not a missing feature: under Chilean financial regulation (Ley Fintec), handing someone a specific portfolio is investment advice. Staying on the calculator side of that line shaped most of the architecture, and the project was rewritten twice to hold it — first from Streamlit to FastAPI, then stripping accounts and social features out of a version that had grown well past the calculator it should have been.

What it does

  • Sensitivity analysis. A Monte Carlo simulation of 250 samples perturbs the expected returns and reports the 5th–95th percentile weight range per asset, so you can see which allocations are actually robust to your own estimates being wrong.
  • Shareable calculations. A share link stores the inputs, never the result — opening it recomputes from scratch. The question is the durable thing; the answer is derived.
  • Everything exportable. Any table downloads as CSV, so you leave with the numbers rather than a screenshot.

How it's built

The calculation engine lives in a core/ package that never imports FastAPI, which means it's unit-testable in isolation and was verified against golden-value regression tests to prove numeric parity survived the Streamlit migration. One performance note I'm fond of: the sensitivity analysis originally used cvxpy and took 26 seconds; rewritten against SciPy's SLSQP it runs 250 simulations in about one.

There are no sessions and no accounts, so the app holds no state between requests and scales horizontally without anything shared.

02

Inmob

Real estate investment analysis

Live Personal project

Inmob answers a question every Chilean property buyer asks and almost nobody answers properly: is this actually a good investment? You enter the purchase and financing parameters, and it returns ROI, IRR, NPV, cap rate, the full cash flow schedule, and a technical verdict on the deal.

The whole model runs in UF, Chile's inflation-indexed unit of account, rather than nominal pesos. That single decision removes the need to model inflation separately — returns come out real by construction.

What it does

  • Full DCF analysis of a property purchase, with the assumptions visible and editable rather than buried.
  • Rental yield map by comuna, rendered as a choropleth with GeoPandas, for comparing neighbourhoods before comparing individual properties.
  • Mortgage calculator in UF/CLP, fed by the daily UF value and Chilean regulator (CMF) mortgage rate data.
  • Excel and PDF export, because this is the kind of analysis people need to send to someone else.

How it's built

Same architectural rule as Marko-Viz: core/ and data_access/ never import FastAPI. The two projects deliberately share their logging and data-access design, documented as playbooks so the pattern can be replicated rather than reinvented — and the database swaps from SQLite to PostgreSQL by changing one environment variable.

The multi-step wizard keeps no server-side session state — it travels in hidden form fields — so the app runs under four Gunicorn workers without sticky sessions.

03

HODL Empire

Finance-themed idle game

Live Side project

An idle/incremental game about the thing my other two projects take seriously. You start as a bedroom trader clicking for cash, then stop clicking and start buying assets that earn for you: trading bots, gaming rigs, servers, datacenters, moon colonies, nuclear plants.

It exists because an idle game is a surprisingly honest exercise in the same maths I use professionally — exponential cost curves, compounding returns, and the point where automation beats effort.

What it does

  • Full game loop with a tick engine, purchasable income sources, upgrades and lifestyle multipliers.
  • Exponential economy — each asset costs baseCost × 1.15^owned, the standard incremental-game curve that keeps every purchase meaningful.
  • Persistent progress, auto-saving every 30 seconds and on page unload.

How it's built

HTML, CSS and JavaScript. That's the whole dependency list — no framework, no bundler, no build step. It's a deliberate constraint: the state management, the save system and the render loop are hand-written, which is the point. It deploys to the same EC2 box as the other two projects, via GitHub Actions over SSH on every push to main.
